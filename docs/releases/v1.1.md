# K1 v1.1: reliability and explicit execution contracts

This release updates the reusable harness while retaining the public package,
CLI, credential environment variables and built-in LIBERO-Pro/RoboSuite adapters.
The previous public main is archived in the `v1.0` branch. No experiment outputs,
credentials, simulator assets or model weights are included.

## What changed

### Grounded perception references

Measurements carry camera/sensor snapshot references. A stored point or visible
region is not silently promoted to a fresh observation after the scene changes.
Persistent IDs retain their records; current visibility and measurement validity
are separate from memory. A valid depth point still does not prove object identity.

Position tools support measured point references plus named world-axis offsets,
reducing the need to copy three floating-point coordinates. Explicit XYZ targets
remain supported. The harness validates frames and arguments; it does not guess
whether the model intended to swap two coordinate axes.

### Clearer robot execution

Motion feedback distinguishes requested goals, achieved robot state and residuals.
New motion updates target bookkeeping so a previous position anchor cannot silently
become the next rotation or gripper command's position intention. Relative moves
retain the per-axis translation limit; absolute transit retains its separate
native command budget and non-progress limit.

Multi-effector targets are validated together before execution. Commands can refer
to the native TCP or, with verified calibration, the finger-pad midpoint.
Orientation always describes native TCP axes. Simultaneous end poses are not a
relative-motion constraint, collision-free path or guarantee of coordinated contact.

Simulator failures after execution begins are treated as uncertain execution, not
as ordinary tool mistakes that can safely be retried. An episode must be restarted
explicitly. Native control-step budgets and physical simulation steps must not be
assumed equivalent across adapters.

### Gripper evidence, not grasp verdicts

Gripper measurements report validity, source and units. The monitor records changes
while commands are held and exposes concise events, rather than repeatedly appending
the same warning. Missing measurements remain unknown. An opening, a stalled closure
or TCP arrival does not certify attachment; the model must inspect the images and
object motion. Event detection is only as reliable as the adapter's calibration.

### Memory and model transport

`history_rounds` still bounds recent detailed text exchanges (default 8), while the
complete episode archive and model-maintained progress remain available. Image history
can select recent decisions or distinct physical states. This prevents repeated
measurement calls at the same state from displacing the last pre-motion image.

Provider reasoning/signature metadata is preserved for conversation continuity,
not treated as supervised decision text. Truncated outputs are not executed; output
budget recovery is bounded and recorded. Infrastructure errors remain distinct from
task failures. No credential is written into model request archives.

## Completion protocol: choose and report it

| `completion_mode` | Behavior |
|---|---|
| `submission_only` | First model `done` ends the attempt. Harness policy/control code does not poll native success. The host scores after the final model call. |
| `feedback` | Native success may stop the episode, and a premature `done` can receive native failure feedback. Identical sensor states reuse the previous completion check. |
| `legacy_autostop` | Native success can stop execution, without the failed-`done` correction protocol. |

For a non-oracle agent evaluation, use:

```yaml
harness:
  completion_mode: submission_only
  completion_feedback: false
  history_rounds: 8
  history_image_rounds: 1
  history_image_selection: distinct_physical_states
```

Merge these fields into a complete example configuration. Do not combine
`completion_feedback: true` with a different explicit mode. Existing examples
retain their feedback-enabled setting for compatibility; changing the mode changes
the experimental protocol, not merely logging. Environment-internal termination
may still occur independently; an adapter must expose that explicitly.

The public paper figures are historical results. This release does not establish
a new accuracy improvement or imply that native-feedback results measure
submission-only performance.

## Installation and validation

Install from this checkout using `python -m pip install -e '.[dev]'`, then run
`python -m pytest` and `python -m ruff check src tests`. Simulator setup remains
separate; see [environment setup](../environments.md). Run the CLI smoke test
before model rollouts in each installed simulator. Synthetic tests cover contracts
and failure paths, but do not prove task success or GPU compatibility.

## Supported scope and adapter obligations

The ready-to-configure adapters in this public distribution remain LIBERO-Pro and
RoboSuite. The shared modules are environment-independent; this is not a claim
that additional simulators can be launched without an adapter or asset setup.

To integrate another simulator, provide calibrated RGB-D and robot proprioception,
explicit arm names and tool capabilities, consistent world/TCP conventions,
measured gripper units and limits, bounded native execution, and clear execution
receipts. Out-of-process adapters must propagate completion mode to the native
process; actor-side suppression alone is insufficient. Never expose hidden object
poses or success geometry as observations. See [architecture](../architecture.md).

Geometric grasp proposals remain visible-surface heuristics, not an arbitrary-object
grasp network. Scores are hidden from the model but still affect proposal selection.
Tracking can lose correspondence, geometry can be occluded, and models can choose
incorrect actions despite accurate tools. These limitations are not solved by a
release-version change.
